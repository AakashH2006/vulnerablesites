🚨 The Vulnerability — Unrestricted File Upload

When a server accepts file uploads without validating file type or content, an attacker can upload a web shell (e.g. shell.php) to the web-accessible upload directory. Once uploaded, they can execute arbitrary system commands by visiting the file URL.

// ❌ VULNERABLE — no validation
app.post('/upload', upload.single('file'), (req, res) => {
  // File saved directly to /uploads/ with original name
  res.json({ url: '/uploads/' + req.file.originalname });
});
// Attacker uploads shell.php → visits /uploads/shell.php?cmd=cat+/etc/passwd

✅ The Fix

Validate file type server-side (not just the extension — check MIME type and file magic bytes), store outside the web root, and serve through a controlled endpoint.

// ✅ SAFE approach
const ALLOWED_MIME = ['image/jpeg','image/png','image/gif','image/webp'];
app.post('/upload', upload.single('file'), (req, res) => {
  if (!ALLOWED_MIME.includes(req.file.mimetype)) return res.status(400).send('Invalid type');
  const safeId = crypto.randomUUID();
  // Store outside web root: /var/private/uploads/{safeId}
  fs.renameSync(req.file.path, `/var/private/uploads/${safeId}`);
  res.json({ url: `/files/${safeId}` }); // served via controlled endpoint
});
