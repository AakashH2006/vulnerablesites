🚨 The Vulnerability — SQL Injection

SQL Injection occurs when user-controlled input is directly concatenated into a SQL query string without sanitisation or parameterisation. The server builds a query like:

SELECT * FROM users WHERE username = '[INPUT]' AND password_hash = '...'

By injecting ' OR '1'='1 the query becomes logically always-true:

SELECT * FROM users WHERE username = '' OR '1'='1'--' AND password = '...'
-- The WHERE clause is ALWAYS TRUE → returns ALL rows → attacker logs in as first user (often admin)

✅ The Fix — Parameterised Queries

Never concatenate input into SQL strings. Use parameterised queries / prepared statements so the database engine treats input as data, never as code:

// ❌ VULNERABLE — string concatenation
const query = `SELECT * FROM users WHERE username = '${username}'`;

// ✅ SAFE — parameterised query (node-postgres example)
const result = await db.query(
  'SELECT * FROM users WHERE username = $1 AND password_hash = $2',
  [username, hashPassword(password)]
);
